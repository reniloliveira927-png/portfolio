~/projects/deepsnap // node_01

DeepSnap — AI Photo Booth for Events

A SaaS prototype that turns any event into a branded, AI-powered photo experience.

Problem

Event and live-marketing producers wanted personalized photo experiences, but traditional booths relied on manual editing, offered no brand flexibility, and took too long to deliver results to guests.

Solution

An end-to-end platform: producers configure each event, set the visual style through an AI prompt, and upload a custom frame. Guests step up to the booth, the AI transforms their photo in the chosen style, and it lands in the live event gallery in seconds.

Technical challenge

Balancing quality and speed. I built a streaming pipeline so guests watch the image form in real time, tuned the model to preserve face, identity and pose, and handled the messy edge cases — camera permissions, mirrored front cameras, timezone drift between server and browser.

~/projects/fae360 // node_02

FAE360 — Live Cube Ranking

A scoreboard for a school cube-solving tournament that updates itself, live, on the big screen.

Problem

At a school cube-solving tournament, staff needed to log competitors' times and update the scoreboard instantly — manual math and slow updates don't work live, in front of a crowd.

Solution

An operator panel for entering name, school and time, paired with a big-screen display that reorders itself automatically. Times convert to milliseconds on entry for exact sorting, the board holds a clean top 10 with the podium highlighted, and every change syncs to the screen in real time.

Technical challenge

Getting the sync and motion right: edits from the operator panel needed to reach the screen instantly on a different device, ranks had to animate smoothly as positions shifted, and the top 10 had to fit a 16:9 screen with no scrolling — all inside FAE360's own visual identity.

React 19 TypeScript TanStack Start / Router Tailwind CSS v4 Framer Motion Lovable Cloud (real-time DB)

~/projects/fae-vault // node_03

FAE Vault — Binary Code Challenge

An interactive booth game that teaches binary-to-decimal conversion by making you crack a vault.

Problem

FAE wanted a fun, hands-on activity for campus events — something that would teach a real computer science concept while feeling like a game, not a lecture.

Solution

A "vault" the participant has to crack by reading binary. An onboarding screen explains bit weights (8·4·2·1), then the vault shows four rows of glowing bits — the participant converts each row to a digit and types the 4-digit code on a numeric keypad. Get it right and the vault unlocks with confetti, a binary "code rain" wipe, and a synthesized unlock sound; three wrong tries lock the round.

Technical challenge

Keeping the dynamic password, its live binary rendering, and the attempt counter perfectly in sync — the code is redrawn as bit-bubbles in real time, and progressive hints have to help without ever leaking the answer. A validation effect kept re-firing and locking the game early; fixed by moving the attempt count into a useRef for synchronous, race-free counting.

React 18 TypeScript 5 Vite 5 Tailwind CSS + shadcn/ui Framer Motion Web Audio API Vibration API Vitest

note_ fully client-side — no backend, no data collected on participants.

~/projects/portonave-journey // node_04

Portonave Container Journey — Port Mini-Games

A pixel-art mini-game series that turns real container-port operations into playable levels.

Problem

Portonave (a container terminal) wanted a way to show visitors and staff what actually happens on the terminal floor — in a form more memorable than a slideshow.

Solution

A pixel-art game with two playable phases. Phase 1 puts you at the gate: a truck rolls in, you compare its plate, container ID and time slot against the system and approve or reject it before the clock runs out. Phase 2 moves you to the yard: a 5×5 grid puzzle where you slide cargo containers around red blockers to reach the crane and extract them, scored on how close you get to the optimal number of moves.

Technical challenge

Computing the true minimum number of moves for the yard puzzle, live, as the player moves. I wrote a BFS solver that treats the board as a sliding-piece puzzle, with memoized canonical states, a depth cap and a heuristic fallback — its output sets both the player's move budget (1.2× optimal) and a "path blocked" warning pulse.

React 18 TypeScript 5 Vite 5 Tailwind CSS + shadcn/ui React Router Web Audio API BFS solver Vitest

note_ fully client-side — progress passed between phases via localStorage and URL params.

~/projects/warehouse-map // node_05

Warehouse Inventory — Interactive Floor Map

A split-screen inventory tool that shows exactly where every item lives.

Problem

Inventory was confusing to manage — nobody could tell where an item actually sat in the warehouse, and even simple stock updates meant slow, clumsy navigation through disconnected lists.

Solution

A split-screen app: an item list with search and filters on one side, an interactive 2D floor plan on the other. Click an item and its exact shelf lights up on the map; click a shelf and its items appear. Quick stock-outs, custom-quantity removals and deletions all sync instantly across the list, counters and map.

Technical challenge

Tuning the map's zoom and pan so the floor plan always framed correctly — never too tight, never too loose. Solved by capping min/max scale, centering the initial view, and calibrating wheel and pinch sensitivity by hand.
